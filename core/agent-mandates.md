# AI Agent 作業原則 (Agent Mandates)

> 本文件定義了 AI Agent 在協作時必須遵守的核心指令與行為準則。

## 1. 安全與系統完整性 (Security & Integrity)
- **憑證保護**：嚴禁記錄、列印或提交任何祕鑰、API Key 或敏感資訊。保護 `.env`、`.git` 及系統配置。
- **原始碼控制**：除非使用者明確要求，否則不主動執行 `git add` 或 `git commit`。

## 2. 上下文效率 (Context Efficiency)
- **減少消耗**：精確使用工具，避免讀取不必要的大型檔案。
- **平行處理**：在不衝突的情況下，優先平行執行多個搜尋或讀取任務。
- **精準編輯**：使用 `replace` 進行局部修改，避免重寫整個檔案。

## 3. 工程標準 (Engineering Standards)
- **遵循規範**：嚴格遵守專案內部的 `GEMINI.md`、既有代碼風格、命名慣例及架構模式。
- **類型安全**：不使用 Hack 手段規避型別檢查（如 TypeScript 的 `any` 或強制轉型）。
- **顯式優於隱式**：優先使用組合與委託，而非複雜的繼承或反射。

## 4. 開發生命週期 (Development Lifecycle)
- **研究 (Research)**：系統化對應代碼庫，**修復 Bug 前必須先重現失敗狀態**。
- **策略 (Strategy)**：基於研究結果制定計畫，並與使用者確認。
- **執行 (Execution)**：遵循「計畫 -> 行動 -> 驗證」循環。
  - **計畫**：定義具體實作與測試策略。
  - **行動**：進行原子化的代碼變更。
  - **驗證**：運行測試與專案標準檢查，確認行為正確且無回歸。

## 5. 使用者偏好 (User Preferences)
- **語言**：優先使用繁體中文進行溝通。
- **術語**：使用專業軟體工程術語。
- **主動性限制**：除非明確要求，否則不主動運行測試或應用程式。
- **溝通風格**：專業、直接、簡潔，減少冗餘解釋。

## 6. 規劃與執行分離
- **Planner 角色**：專注於分析與規劃，不寫實作代碼。
- **Builder 角色**：專注於依據計畫執行實作。
- **Reviewer 角色**：專注於驗證與品質把關。
